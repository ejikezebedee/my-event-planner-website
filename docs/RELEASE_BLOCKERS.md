# Release-blocking defects (§46) — verdict

Each defect class from the master prompt was audited against the delivered
tree. Evidence: automated suites (72 API e2e, 42 unit, 30 browser — all
passing) plus the targeted code/repository audits noted below. **None of the
sixteen defects is present.**

| #   | Defect                                           | Verdict   | Evidence                                                                                                                                                                                                                                                                                 |
| --- | ------------------------------------------------ | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Money handled as floats                          | **Clear** | All monetary values are integer minor units: `moneySchema = z.number().int()`, Prisma money columns are `BigInt`, parsing is string-based (`parseMoneyToMinor` — no float arithmetic), sums use `BigInt` reducers. The only division is display formatting. Covered by money unit tests. |
| 2   | Login or session instability                     | **Clear** | Auth e2e: register/login/logout, session revocation on logout (401 immediately after), sliding-renewal sessions hashed with sha256, 30 browser tests all authenticate through the real UI.                                                                                               |
| 3   | Production secrets committed                     | **Clear** | Repository scan: no `.env` files tracked, `.env.example` contains placeholders only, the only literal credentials are the documented demo-seed accounts used by tests.                                                                                                                   |
| 4   | Cross-workspace data leakage                     | **Clear** | Security suite (9 tests) + hardening suite (10 tests) + DoD steps 27–28: foreign events/expenses/payments/guests/tasks/documents/reports/calendar/timeline/budget/vendors → 404, foreign workspace data → 403, notification isolation.                                                   |
| 5   | Missing authorization checks                     | **Clear** | Global session guard on every controller; every domain service calls `assertEventAccess`/`assertEventWrite`/`assertWorkspaceRole`; controllers with direct Prisma access audited (dashboard is role-scoped, session routes are user-scoped); viewer read-only enforced (403 in e2e).     |
| 6   | Incorrect refund math                            | **Clear** | Refund lifecycle e2e (partial → full → `refunded`), refundable-limit 409, refund-of-refund 400, refund-aware paid sums in dashboard, budget, vendor summaries, and event overview (regression test). Reversals recompute status.                                                         |
| 7   | Duplicate calendar entries after record updates  | **Clear** | Auto calendar items are computed on read with stable source keys (`task:5`, `expense:9:due`) and Map-deduped — duplicates are impossible by construction. 6 unit tests + calendar e2e.                                                                                                   |
| 8   | Timeline silently overwriting entries            | **Clear** | Manual timeline updates target a single `(id, eventId)` row; auto entries are computed on read and never persisted; the merged-feed e2e verifies both coexist.                                                                                                                           |
| 9   | Overwritten or deleted financial history         | **Clear** | Payments are never deleted — reversals set `reversedAt` and preserve the original record; expenses with payments are cancelled, not deleted; budget-item delete is `onDelete: SetNull` on expenses; every mutation writes an audit-log entry.                                            |
| 10  | Broken CSV import                                | **Clear** | Operational e2e (template download, dry-run preview, import with duplicate/error handling) + DoD step 11 + live check (1 imported / 1 duplicate / 1 row error).                                                                                                                          |
| 11  | Public document exposure                         | **Clear** | Downloads require event access (security e2e: outsider 404), storage keys are random and traversal-proof, uploads are magic-byte validated, everything serves as `attachment`.                                                                                                           |
| 12  | Horizontal page overflow on mobile widths        | **Clear** | Playwright hardening suite: 11 pages (5 public + 6 app) at 390×844 assert zero horizontal overflow.                                                                                                                                                                                      |
| 13  | Broken mobile navigation                         | **Clear** | Playwright: hamburger opens the drawer at 390px and navigates to Calendar.                                                                                                                                                                                                               |
| 14  | Outdated UI screenshots or placeholders          | **Clear** | All 19 evidence screenshots are real captures of the current UI (`01-landing.png` refreshed to the Phase 7 landing); the landing page preview is a real product screenshot; no stock imagery or lorem ipsum anywhere in the codebase.                                                    |
| 15  | Seed data automatically inserted into production | **Clear** | Seed runs only via the explicit `pnpm seed` script — verified: no Dockerfile, compose service, entrypoint, or application boot path invokes it.                                                                                                                                          |
| 16  | Unhandled server errors                          | **Clear** | Global exception filter returns a uniform `{statusCode, message, path, timestamp}` envelope without internals; web has custom 404, root and app error boundaries, and an "Event not found" state; health endpoints (`/health`, `/health/ready`) report liveness/readiness.               |
